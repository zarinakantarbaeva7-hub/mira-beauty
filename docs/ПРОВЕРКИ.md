# Как проверить проект

Эта памятка содержит сценарии. Статус успешного прохождения нужно подтверждать фактическим запуском проверок, а не наличием списка.

## Автоматические проверки

Из папки проекта в PowerShell:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

Если в поставке есть отдельный отчёт о выполнении, сверяйте его с текущей версией исходников. После изменения кода запускайте связанные проверки заново.

## Основной пользовательский сценарий

1. Откройте главную страницу и перейдите по всем пунктам меню.
2. В каталоге выберите категорию. Введите существующее название, затем заведомо отсутствующий запрос; проверьте пустое состояние.
3. Выберите мастера или услугу и перейдите к записи. Проверьте, что соответствующий выбор перенёсся в форму.
4. Выберите дату, свободное время и вымышленные имя и телефон. Отметьте согласие и отправьте заявку.
5. Убедитесь, что показан уникальный номер. Повторно откройте дату и мастера: занятое время не должно предлагаться.
6. Войдите в админку, найдите эту запись и проверьте данные. Обновите страницу: запись должна остаться.
7. Отмените запись и проверьте, что освободившееся время снова доступно.

## Некорректные данные

- Отправка пустой формы показывает обязательные поля.
- Номер `abc` отклоняется.
- Прошедшая дата и прошедшее время текущего дня не доступны для записи.
- Подмена услуги или мастера, несовместимая пара, отсутствие согласия и неверный формат времени отклоняются сервером.
- Сервер не должен создавать запись после ответа с ошибкой.
- Повторный запрос на пересекающийся интервал возвращает конфликт, а не вторую запись.

Для доказательства серверной проверки используйте DevTools → Network и автоматические тесты. Клиентское сообщение браузера само по себе не доказывает проверку backend.

## Доступ администратора

- Без входа кабинет и CSV не раскрывают контакты.
- Неверный пароль не даёт доступ.
- После выхода кабинет снова требует вход.
- Изменение статуса без корректного CSRF-токена отклоняется.
- Все поддерживаемые статусы сохраняются после обновления страницы.

## Телефон и изображения

Проверьте ширины 360, 390, 768 и 1440 пикселей в инструментах браузера, затем настоящий телефон по инструкции README. Нет горизонтальной прокрутки, обрезанных полей, перекрывающих кнопок и исчезающего меню. Текст должен читаться без увеличения масштаба.

У разных услуг, мастеров и работ должны быть разные локальные иллюстрации. В Network не должно быть ошибок 404 для CSS, JavaScript и изображений.

## Скриншоты для защиты

Подойдут главная страница на компьютере, каталог на телефоне, выбор времени, подтверждение с номером, ошибка формы, кабинет и окно Python-оператора. Снимайте только тестовые данные. Папка для файлов — `docs/screenshots/`.

## Размещение

После размещения повторите отправку заявки и вход в админку по публичной HTTPS-ссылке. Проверьте сайт с телефона через мобильный интернет. Локальная проверка и запись исходников на GitHub не заменяют эту проверку.
