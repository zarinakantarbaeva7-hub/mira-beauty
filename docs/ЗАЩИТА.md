# Защита ПМ 6 — план на 5–6 минут

План соответствует вопросам из «Основные вопросы для защиты по ПМ 6.docx». Сделайте шесть слайдов и подготовьте работающий сайт в браузере, VS Code с кодом и Python-приложение оператора. Не выдавайте иллюстрации за фотографии настоящих работ салона.

## Слайд 1. Название и задача — 35 секунд

«Mira Beauty — учебный сайт салона красоты. Он помогает выбрать услугу, мастера и свободное время, а администратору — обрабатывать записи. Отдельное Python-приложение показывает локальные заявки».

Покажите главную страницу. Уточните, что контент демонстрационный, а отправка формы, сохранение и проверка времени действительно реализованы.

## Слайд 2. Python-приложение — 50 секунд

Откройте `operator_app.py`, покажите окно и заявку с сайта. Отправьте новую заявку, обновите список, покажите доступный экспорт. Сохраните собственный скриншот окна для слайда.

Объясните библиотеки: `tkinter` и `ttk` создают окно и таблицу, `sqlite3` читает базу, `csv` формирует файл экспорта. Найдите в коде класс окна и методы обновления списка и экспорта; покажите небольшой фрагмент, который сможете разобрать построчно.

Пример запроса для объяснения — найдите его фактический вариант в `operator_app.py`:

```sql
SELECT id, name, phone, service, visit_date
FROM bookings
ORDER BY created_at DESC
```

«SELECT читает нужные поля, ORDER BY выводит последние заявки первыми. Приложение получает результат и добавляет строки в таблицу».

## Слайд 3. Frontend и адаптивность — 50 секунд

Покажите главную, услуги, мастеров, портфолио и запись. На услугах примените категорию и поиск. Уменьшите окно браузера или включите мобильное устройство в DevTools. Покажите, как перестраиваются карточки, меню и форма.

HTML задаёт структуру, CSS — оформление и сетки, JavaScript — фильтры, доступное время и отправку формы. Шаблоны Jinja используют общую основу страницы и данные Python. Изображения локальные, поэтому сайт не зависит от доступности чужого фотосервиса.

## Слайд 4. Backend: запрос → обработка → результат — 65 секунд

Откройте DevTools → Network, выберите услугу, мастера и дату. Покажите запрос доступного времени. Затем отправьте тестовую заявку и откройте POST `/api/bookings`: Payload — данные формы, Response — номер заявки, статус успешного создания.

Цепочка для схемы на слайде:

**Клиент выбирает данные → JavaScript отправляет JSON → Flask проверяет поля и занятость → SQLite сохраняет заявку → HTTP 201 и JSON → подтверждение в браузере.**

Покажите обработчик `/api/bookings` в `app.py`. Объясните: backend написан на Python с Flask; при локальном запуске запросы обслуживает Waitress. `jsonify` формирует JSON-ответ.

## Слайд 5. Данные и доступ — 55 секунд

База — SQLite, локальный файл `instance/beauty.sqlite3`. В ней хранятся записи и данные входа администратора. Значения передаются в SQL параметрами. Сервер повторно проверяет данные, даже если клиентская проверка уже пройдена.

Свободное время вычисляется с учётом мастера, даты и длительности процедуры. Проверка занятости и создание записи выполняются в транзакции. Две пересекающиеся записи к одному мастеру не должны одновременно занять интервал.

Войдите в админку: покажите записи, поиск/фильтр, смену статуса и CSV. Пароль хранится как хеш; кабинет и экспорт требуют входа, изменения защищены CSRF-токеном. Контакты клиентов не выдаются публичным списком.

## Слайд 6. Результат, проверки и развитие — 55 секунд

Покажите успешное подтверждение заявки. Затем ошибку: неверный телефон или уже занятое время. После первой записи снова откройте выбор времени: занятый интервал должен исчезнуть.

Запустите проверки из `tests/` и показывайте фактический результат выполнения. Подготовьте скриншоты успешной операции и сообщения об ошибке; при наличии используйте готовые файлы из `docs/screenshots/`.

Трудности: связать несколько страниц, согласовать данные frontend/backend, учесть длительность и занятость мастеров, ограничить доступ к админке и сохранить адаптивность.

Что можно улучшить: реальные уведомления, управление расписанием и выходными, резервное копирование по расписанию, личный кабинет клиента. Эти возможности не следует называть уже реализованными.

## Подготовка перед выступлением

- Используйте только вымышленные контакты в заявках и скриншотах.
- Запустите сайт и оператор заранее, проверьте вход администратора.
- Подготовьте скриншот Python-окна, десктопа, телефона, успеха и ошибки.
- В VS Code откройте понятные фрагменты: обработчик формы, проверку времени, параметризованный SQL и JavaScript `fetch`.
- Сохраните локальную копию: публичная ссылка зависит от доступности хостинга и интернета.
- Уложитесь в 5–6 минут; основное внимание уделите взаимодействию браузера и сервера.
