# RepairLab — сайт мастерской для защиты ПМ 6

Учебный полный проект: HTML + CSS + JavaScript, Python WSGI, SQLite и локальное приложение оператора на Tkinter. Без сборщика, внешних картинок и JS-библиотек. Иллюстрации разные, включены в проект.

## Быстрый запуск в VS Code

1. Установите Python 3.10 или новее (на Windows включите Add Python to PATH), VS Code и расширение Microsoft Python.
2. Распакуйте проект. В VS Code: **Файл → Открыть папку → repairlab**. Откройте встроенный терминал.
3. Запустите:

```bash
python app.py
```

На macOS/Linux команда может называться `python3`. Откройте **http://localhost:8000**. Для локального сайта установка пакетов не нужна. Не открывайте HTML двойным щелчком и не используйте Live Server: он не запускает Python API.

4. Во втором терминале запустите приложение оператора:

```bash
python operator_app.py
```

Нажмите «Обновить» после отправки заявки. Двойной запуск базы не нужен — оба процесса используют `data/requests.sqlite3`. Если Tkinter отсутствует на Linux, установите пакет `python3-tk`; стандартный установщик Python для Windows обычно включает его.

Есть текстовый режим без графического окна:

```bash
python operator_app.py --list
```

Для отладки откройте «Запуск и отладка» в VS Code: конфигурации сайта и оператора уже созданы.

## Что работает

- Каталог четырёх типов устройств с отдельными локальными SVG и фильтрами.
- Выбор устройства в карточке переносит его в форму.
- Проверка имени, телефона, даты (сегодня — 90 дней вперёд), описания и согласия в браузере и на сервере.
- POST-запрос, сохранение в SQLite и ответ с уникальным номером заявки.
- Ошибки формы, ошибки сети и блокировка кнопки на время отправки.
- Python-приложение: список заявок, просмотр описания, смена статуса, экспорт CSV.
- Адаптивная вёрстка, клавиатурный фокус, доступные названия элементов, страница обработки данных.

Сервис не отправляет SMS и письма, не принимает оплату, не бронирует время автоматически и не выполняет реальный ремонт. Цены и название вымышленные. Используйте тестовые персональные данные.

## Как работает запрос

Браузер выполняет `GET /api/services` для каталога. При отправке формы `fetch('api/requests', {method: 'POST', ...})` передаёт JSON. Функция `application` в `app.py` разбирает запрос, `validate` проверяет поля. `sqlite3.connect` открывает базу, `execute` с параметрами `?` добавляет запись; контекст `with` подтверждает транзакцию. Сервер возвращает HTTP 201 и JSON с номером; JavaScript выводит результат через `textContent`. При ошибочных данных возвращается HTTP 422, запись не создаётся.

## Данные и ограничения

База и персональные данные не входят в Git (`data/` в `.gitignore`). Публичного API чтения заявок нет. Учётные записи и веб-админка не предусмотрены: доступ оператора ограничен доступом к машине и файлу базы. SQL параметризован, вывод сообщений через `textContent`, размер тела запроса ограничен 8 КБ, файлы сервера за пределами `static/` не выдаются. Сервер задаёт CSP и `nosniff`.

Это учебный прототип. Для реального потока посетителей нужны защита от спама/ограничение частоты, резервные копии, регламент хранения и полноценная авторизация при добавлении удалённой админки. Не публикуйте базу и не включайте реальные данные в скриншоты.

## Проверки

```bash
python -m unittest discover -s tests -v
```

6 тестов: каталог и разные картинки, запись в БД, отсутствие публичного списка и доступа к серверным файлам, ошибочные поля без сохранения, повреждённые/большие JSON и защита SQL-параметризацией, отдача страниц.

Проверки браузером описаны в `docs/ПРОВЕРКИ.md`. Скриншоты находятся в `docs/screenshots/`. Абсолютное отсутствие багов не гарантируется; в документации перечислены выполненные проверки и ограничения.

## Телефон

При локальном запуске подключите телефон и компьютер к одной Wi-Fi сети. Узнайте локальный IPv4 компьютера (`ipconfig` на Windows) и откройте на телефоне `http://IP-КОМПЬЮТЕРА:8000`. Разрешите Python в брандмауэре только для частной сети. Это локальный адрес, доступный пока работает компьютер, не постоянная ссылка в интернете.

## GitHub и постоянная ссылка

GitHub хранит исходный код. **GitHub Pages не запускает Python и SQLite**. Чтобы форма работала по публичной ссылке, разместите весь проект как Python Web Service, например на Render:

1. Загрузите папку проекта в отдельный репозиторий GitHub (или используйте указанную папку существующего репозитория).
2. В Render подключите репозиторий и создайте Blueprint. Для текущего репозитория задайте **Blueprint Path: repairlab/render.yaml**. В конфигурации уже указан `rootDir: repairlab`. Если перенесёте содержимое папки в корень отдельного репозитория, удалите строку `rootDir: repairlab` и используйте Blueprint Path `render.yaml`.
3. Проверьте тариф перед созданием. Конфигурация использует **платный Starter и постоянный диск 1 ГБ**. Автоматически платный сервис в рамках этой работы не создавался. Цена зависит от условий хостинга.
4. Build: `pip install -r requirements.txt`. Start: `gunicorn app:application --bind 0.0.0.0:$PORT --workers 1 --threads 4`.
5. Подключите постоянный диск к `/var/data`, переменная `DB_PATH=/var/data/requests.sqlite3`. Не храните SQLite на временном диске: заявки исчезнут после пересборки.
6. После успешного развёртывания хостинг выдаст HTTPS-ссылку `https://<имя-сервиса>.onrender.com`. Откройте её с телефона и отправьте тестовую заявку.

Локальное приложение оператора работает с **локальной** базой. После развёртывания оно не синхронизируется с сервером автоматически: для демонстрации запустите сайт и оператор локально. Для удалённого оператора потребуется отдельный защищённый API или безопасная передача копии базы администратором.

На GitHub через сайт: Add file → Upload files, загрузите распакованное содержимое. Чтобы скачать уже загруженный проект: Code → Download ZIP, затем откройте нужную папку в VS Code.
