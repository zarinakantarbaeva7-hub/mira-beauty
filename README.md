# Mira Beauty

Учебный сайт салона красоты для защиты ПМ 6: несколько страниц, каталог услуг, мастера, портфолио, запись на свободное время и кабинет администратора. Frontend — HTML, CSS и JavaScript. Backend — Python и Flask. Заявки и учётные записи хранятся в SQLite. Для показа отдельного Python-приложения предусмотрен локальный оператор на Tkinter.

Контент, цены и имена мастеров демонстрационные. Реальные фотографии взяты из Pexels; источники указаны в docs/ИСТОЧНИКИ_ФОТО.md. Для проверки используйте вымышленные контакты. Сайт не оказывает реальные услуги и не отправляет SMS или письма.

## Запуск на Windows — самый простой способ

1. Распакуйте архив в обычную папку. Откройте именно ту папку, в которой находятся `app.py`, `requirements.txt` и `START.bat`.
2. Если предыдущий сайт уже работает на порту 5000, остановите его в прежнем терминале сочетанием **Ctrl + C**.
3. Дважды нажмите **START.bat**. При первом запуске он создаст окружение `.venv` и установит зависимости. Нужен установленный Python 3.10 или новее и интернет для установки пакетов.
4. Создайте администратора: введите логин и дважды пароль длиной от 8 символов. **Символы пароля в консоли не отображаются — это нормально.** Запомните выбранные данные: готового общего пароля в проекте нет.
5. После запуска откроется браузер. Адрес сайта: **http://127.0.0.1:5000**. Если окно браузера не открылось, введите этот адрес вручную.
6. Оставьте консоль открытой: в ней работает сервер. Для остановки нажмите **Ctrl + C**. Если Windows спросит о завершении пакетного файла, подтвердите его.

Повторный запуск не требует создания того же администратора. Данные сохраняются в `instance/beauty.sqlite3` и остаются после перезапуска. Не удаляйте папку `instance`, если хотите сохранить заявки и учётные записи.

## Если после скачивания видны прежние рисунки

Открытая вкладка `127.0.0.1:5000` может показывать сервер, запущенный из старой папки. Скачивание ZIP не заменяет работающий экземпляр.

1. Полностью распакуйте свежий ZIP в новую папку через «Извлечь всё».
2. Если нужны прежние заявки и администратор, до запуска скопируйте папку `instance` из старого проекта в новый.
3. В новой папке дважды нажмите **START_PHOTOS.bat**. Он использует тот же backend и подготовку окружения, но запускает эту копию на **http://127.0.0.1:5019**.
4. Дождитесь сообщения о запуске и откройте **http://127.0.0.1:5019/services**. На первой карточке должна быть фотография стрижки, на второй — фотография окрашивания.
5. Оставьте окно запуска открытым. Если порт 5019 занят, остановите предыдущий запуск START_PHOTOS через Ctrl+C.

## Запуск из VS Code

Откройте папку проекта через **File → Open Folder**, затем **Terminal → New Terminal**. В PowerShell выполните по очереди:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py setup-admin
.\.venv\Scripts\python.exe app.py
```

Если `.venv` уже создана, первую команду можно пропустить. Активировать окружение не требуется. Сайт запускается через Python; расширение Live Server не выполняет серверную часть.

Для отладки установите расширения Microsoft Python и Python Debugger. В **Run and Debug** есть конфигурации сайта и приложения оператора для Windows.

На macOS/Linux используйте `python3`, а путь к Python внутри окружения — `.venv/bin/python`.

## Что проверить после запуска

1. Откройте «Услуги», выберите категорию и попробуйте поиск.
2. Перейдите к записи, выберите услугу, подходящего мастера и дату. Время загружается с сервера; недоступные интервалы не предлагаются.
3. Отправьте форму с вымышленными именем и телефоном. Сохраните выданный номер.
4. Войдите в кабинет администратора под созданным логином: проверьте запись, смените статус, попробуйте поиск и экспорт CSV.
5. Попытайтесь записаться к тому же мастеру на занятый интервал. Сервер проверяет пересечение с учётом длительности процедуры.
6. Попробуйте неверный телефон и пустые поля: форма должна объяснить ошибку. Для проверки ответа именно Python-сервера используйте сценарии из [памятки проверок](docs/ПРОВЕРКИ.md).

Рабочий день: с 10:00 до 18:00, шаг выбора начала — 30 минут. Процедура должна завершаться до конца рабочего дня. Прошедшее время исключается; расчёт ведётся по часовому поясу **Asia/Qyzylorda**. Новая и подтверждённая запись занимают интервал. Отменённая запись освобождает его.

## Отдельное Python-приложение

Откройте второй терминал, пока сайт работает, и выполните:

```powershell
.\.venv\Scripts\python.exe operator_app.py
```

Приложение показывает заявки из той же **локальной** базы. После отправки новой заявки обновите список. Это удобно для скриншота и объяснения Tkinter, SQLite и обработки данных на защите.

После размещения сайта на хостинге серверная база будет отдельной. Локальный оператор автоматически не синхронизируется с ней. Для работы с опубликованным сайтом используйте его защищённую веб-админку.

## Телефон в той же Wi-Fi сети

Это проверка адаптивности на реальном устройстве. Компьютер и телефон должны быть подключены к одной частной Wi-Fi сети.

1. Остановите локальный сервер сочетанием **Ctrl + C**.
2. В PowerShell VS Code выполните:

```powershell
$env:MIRA_HOST = "0.0.0.0"
.\.venv\Scripts\python.exe app.py
```

3. В другом терминале выполните `ipconfig` и найдите IPv4-адрес активного Wi-Fi подключения, например `192.168.1.15`.
4. На телефоне откройте `http://192.168.1.15:5000`, подставив свой адрес. Если брандмауэр Windows запросит доступ, разрешите его для частной сети.

Адрес работает, пока включён компьютер и запущен сервер. Для ссылки в интернете нужен хостинг. Чтобы вернуть доступ только с компьютера, остановите сервер, выполните `Remove-Item Env:MIRA_HOST` и запустите его снова.

## Какие файлы объяснять на защите

| Файл или папка | Назначение |
| --- | --- |
| `app.py` | Маршруты Flask, проверка формы, свободное время, сохранение в БД и вход администратора |
| `templates/` | Страницы Jinja; общий шаблон и отдельные страницы |
| `static/style.css` | Цвета, сетки, оформление и медиазапросы |
| `static/script.js` | Действия пользователя, фильтры и запросы к серверу |
| `static/images/` | Разные локальные фотографии |
| `operator_app.py` | Отдельное оконное приложение Python |
| `instance/` | Создаваемые при запуске база и секрет сессии; в GitHub не загружаются |
| `tests/` | Автоматические проверки |
| `docs/` | Сценарии проверки, план защиты и размещение |

Основная цепочка: пользователь выбирает данные → JavaScript отправляет JSON → Flask проверяет поля и время → SQLite сохраняет запись → сервер возвращает номер → страница показывает результат.

## Доступ и данные

- Пароли администраторов хранятся в виде хешей. Публичного списка контактов клиентов нет.
- Кабинет и экспорт CSV доступны после входа. Изменения выполняются с проверкой CSRF-токена.
- SQL-запросы используют параметры. Занятость проверяется внутри транзакции.
- Секрет сессии сохраняется локально в `instance/`. Для хостинга можно задать переменные `MIRA_DATABASE` и `MIRA_SECRET_KEY`; не публикуйте значение секрета. При работе по HTTPS задайте `MIRA_HTTPS=1`, чтобы сессионная cookie передавалась только по защищённому соединению.
- В `.gitignore` исключены `.venv`, `instance/`, базы и файлы `.env`. При загрузке через сайт GitHub исключения не применяются автоматически: не выбирайте эти папки для ручной загрузки.
- Для резервной копии остановите приложение и скопируйте `instance/` в закрытое место. Не добавляйте копию с персональными данными в репозиторий.

## GitHub и публичная ссылка

GitHub хранит исходный код. **GitHub Pages не запускает Flask и SQLite.** Для работающей формы в интернете нужен Python-хостинг. Пошаговая инструкция для PythonAnywhere: [docs/РАЗМЕЩЕНИЕ.md](docs/РАЗМЕЩЕНИЕ.md).

Публичное размещение не следует считать завершённым до проверки выданной хостингом ссылки и отправки тестовой заявки. Наличие репозитория или адреса в настройках хостинга само по себе не подтверждает работу сайта.
